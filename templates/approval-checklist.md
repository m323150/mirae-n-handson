# 승인 체크리스트 v1

> v1 · 2회차
> - 테스트: 새로 추가하거나 동작이 바뀐 public 메서드에 테스트를 요구하고, 단순 접근자(getter · setter · 생성자)는 제외한다.
> - 치명 이슈: 개인정보 노출, 인증·인가 우회, 서비스 장애를 유발하는 예외 미처리를 정의에 추가했다.
> - 범위 · 컨벤션: 변경한 파일 안의 최소 정리는 허용하고, 컨벤션은 반려(계층 위반 · 예외 삼키기 · System.out · 하드코딩 비밀값)와 경고(경미한 스타일)로 나눈다.

버전: v1. 모든 항목은 "예/아니오"로 답한다. 표시한 항목이 전부 "예"여야 충족이다.
AI 가 만든 변경분 · 외주사 PR 을 머지하기 전에 리뷰어가 대조하는 목록이다. 네 기준이 **모두** 충족되어야 승인이다. 하나라도 미충족이면 반려.

## 심각도 정의

- **치명** — 그대로 머지하면 서비스나 데이터에 피해를 줄 수 있는 문제. 1건이라도 있으면 반려. 다음 다섯 가지를 치명으로 본다.
  1. 비밀값 · 개인정보(학생 식별자 · 이메일 · 토큰 값) 노출
  2. 데이터 손실 · 정합성 훼손
  3. 인증 · 인가 우회
  4. SQL 문자열 직접 조립에 따른 SQL Injection 가능성
  5. 서비스 장애를 유발할 수 있는 예외 미처리
- **경고** — 지금 고치지 않아도 동작하지만 다음 변경에서 사고가 될 가능성이 있는 문제. 경미한 스타일 위반(변수 · 메서드 네이밍, 코드 정렬 등 기능에 영향이 없는 것)은 경고로 처리하며 승인을 막지 않는다.
- **제안** — 더 나은 방법이 있다는 의견. 승인 · 반려에 영향을 주지 않는다. 목록으로만 남긴다.

이슈 한 건은 심각도 · `파일:줄번호` · 근거 · 수정 방향 네 항목으로 적는다. 근거 줄번호를 댈 수 없는 지적은 "확인 필요"로 따로 둔다.

## 1. 테스트 통과

- [ ] 변경된 모듈의 테스트 명령을 실제로 실행했는가?(실행하지 않고 통과라고 쓰지 않는다)
- [ ] 기존 테스트와 신규 테스트가 모두 통과했는가?(실패 · 오류 0건)
- [ ] 새로 추가했거나 동작이 바뀐 public 메서드(새 엔드포인트 포함)마다 그 동작을 검증하는 테스트가 있는가?(단순 getter · setter · 생성자처럼 별도 로직이 없는 접근자는 제외)
- [ ] 기존 테스트를 지우거나 건너뛰게(`skip`, `@Disabled`) 바꾼 곳이 없는가?

## 2. 치명 이슈 0건

- [ ] 비밀번호 · 토큰 · 키가 코드 · 설정 · 테스트 픽스처에 리터럴로 들어 있지 않은가?
- [ ] 로그 · 응답 · 코드에 개인정보(학생 식별자 · 이메일)나 토큰 값이 노출되는 곳이 없는가?
- [ ] 데이터 손실이나 정합성 훼손(요청에 없는 삭제 · 덮어쓰기, 트랜잭션 없는 다중 쓰기)을 일으키는 코드가 없는가?
- [ ] 인증 · 인가 검사를 우회하거나 제거하는 변경이 없는가?
- [ ] 사용자 입력이 SQL 문자열 조립에 직접 들어가 SQL Injection 이 가능한 곳이 없는가?(파라미터 바인딩 사용)
- [ ] 잡지 않은 예외가 서비스 장애(500 폭증 · 스레드 종료 · 풀 고갈)로 번질 수 있는 경로가 없는가?

## 3. 요청 범위 이탈 없음

- [ ] 요청 문장이 한 문장으로 확인되었는가?(없으면 판정하지 않고 먼저 묻는다)
- [ ] 변경 파일마다 요청된 기능과 직접 관련이 있는가?
- [ ] 요청과 관련 없는 파일을 바꾼 곳이 없는가?(단, 변경한 파일 안의 import 정리 · 사용하지 않는 코드 제거 · 단순 포맷팅은 제외)
- [ ] 의존성 추가 · DB 스키마 변경 · 설정 파일 변경이 있다면 요청에 포함돼 있었는가?

## 4. 컨벤션 준수

반려 사유(하나라도 "아니오"이면 미충족):

- [ ] 팀 `CLAUDE.md` 의 코딩 컨벤션과 금지 사항을 대조했는가?(`convention-check` Skill 이 있으면 그 결과를 쓴다)
- [ ] 컨트롤러에서 Repository · SQL 을 직접 호출하는 등 계층 규칙을 어긴 곳이 없는가?
- [ ] 예외를 잡고 아무 처리 없이 넘기는(빈 `catch` · 예외 삼키기) 곳이 없는가?
- [ ] `System.out.println` 같은 임시 출력이 남아 있지 않은가?
- [ ] 하드코딩된 비밀값이 없는가?

경고(기록만 하고 승인을 막지 않는다):

- [ ] 변수 · 메서드 네이밍, 코드 정렬 같은 경미한 스타일 위반이 없는가?("아니오"이면 경고로 기록)
- [ ] 위 반려 사유에 없는 `CLAUDE.md` 항목(`Clock` 미사용, `console.log`, `any` 등) 위반이 없는가?("아니오"이면 경고로 기록. 로그 · 응답의 학생 식별자와 토큰 노출은 경고가 아니라 치명 이슈 2번)

## 판정 형식

첫 줄에 `판정: 승인` 또는 `판정: 반려`. 이어서 네 기준의 충족 · 미충족 표, 그다음 이슈 목록(심각도 · `파일:줄번호` · 근거 · 수정 방향). 코드는 수정하지 않는다.
