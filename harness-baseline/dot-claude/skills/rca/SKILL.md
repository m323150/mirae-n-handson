# 장애 로그 RCA

대상: incident-logs/$ARGUMENTS/
결과: docs/rca/$ARGUMENTS.md

인자가 없으면 어느 시나리오 폴더인지 먼저 묻는다.

### 절차
1. 수집 범위: 파일을 통째로 읽지 않는다. wc, head, tail, grep -c 로 크기 · 기간 · 타임존을 파악하고 장애 구간을 정한다.
2. 타임라인: 구간 안의 사건을 KST 한 시간축으로 합친다. 모든 줄에 파일:줄번호를 붙인다.
3. 가설: 서로 다른 계층에서 2개 이상. 가설마다 지지 근거, 반증 조건, 확인 방법을 적는다.
4. 검증: 로그로 반증을 시도하고, 남은 가설을 코드 · 설정과 대조해 채택 · 기각한다.
5. 리포트: 요약, 원인, 근거 로그 줄, 수정안, 재발 방지, 모니터링 항목, 확인하지 못한 것.
6. 리포트를 저장하기 전에 이 폴더의 masking-rules.md 규칙을 적용하고 유형별 건수를 남긴다.

### 하지 말 것
- 로그에 없는 줄을 인용하지 않는다. 근거가 없으면 "로그로 확인 불가"라고 쓴다.
- 가장 많이 나온 오류를 곧바로 원인이라고 부르지 않는다.
- 원본 로그와 소스 코드를 수정하지 않는다.
- 마스킹 대응표를 파일로 남기지 않는다.
