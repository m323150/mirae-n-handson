# 변경 영향도 분석

## 반드시 지킬 것
- **코드는 고치지 않는다.** 읽기 · 검색만 한다. 포맷팅 · import 정리도 하지 않는다. `legacy/` 는 특히 그렇다.
- 결과는 답변으로만 보고한다. 사람이 파일 저장을 요청했을 때만 저장한다.
- 모든 항목에 근거 `파일:줄번호` 를 붙이고, 호출 · 쿼리 줄은 1~3줄 인용한다. 근거가 없는 항목은 쓰지 않는다.
- 존재하지 않는 함수 · 파일 · URL 을 쓰지 않는다. 적기 전에 Grep 으로 정의 위치를 확인한다.
- 호출 방향을 뒤집지 않는다. "A 가 B 를 호출한다"는 A 파일의 호출 줄로 확인한다.
- 검색으로 찾지 못한 경로는 "없음"으로 단정하지 않는다. 의심되면 "추적 한계"에 적는다.

## 입력 해석
- `$ARGUMENTS` 가 `파일:줄번호` 면 그 줄을 감싸는 함수 · 메서드 · 프로시저를 대상으로 삼는다.
- 이름만 있으면 Grep 으로 정의를 찾는다. 정의가 여러 개(오버로드 · 같은 이름의 다른 클래스 · 다른 모듈)면 후보를 `파일:줄번호` 로 나열하고 어느 것인지 묻는다.
- 정의를 찾지 못하면 분석을 시작하지 않고 검색한 패턴과 범위를 보고한다.

## 절차
1. **정의 위치**: 대상의 정의 `파일:줄번호`, 시그니처, 소속 모듈을 적는다.
   - 모듈명 → 문서 폴더: `legacy/item-bank-php` → `item-bank`, `legacy/assignment-thymeleaf` → `assignment`, `legacy/grade-mssql` → `grade`, `modern/api` · `modern/web` 은 도메인 패키지 이름.
2. **호출부 역추적**: 직접 호출부를 모두 찾고, 각 호출부를 감싸는 함수를 새 대상으로 삼아 반복한다. 진입점에 닿거나 더 올라갈 호출부가 없으면 멈춘다.
   - 진입점 예: PHP 는 브라우저가 직접 여는 `*.php` 파일(최상위 실행 코드)과 그 파일로 가는 `href` · `form action`; Spring 은 `@GetMapping` · `@PostMapping` 등 매핑 메서드와 URL, 그 URL 을 부르는 템플릿(`th:href` · `th:action`); SQL 프로시저는 `EXEC` · `CallableStatement` · `{call ...}` 로 부르는 코드; React 는 라우트 · 화면 컴포넌트.
   - 검색 패턴은 언어별로 넓게 잡는다: 함수 이름, 메서드 참조(`::name`), 문자열로 쓴 이름(`'name'`, `"name"`), 프로시저 이름(스키마 접두어 `dbo.` 포함 · 미포함 모두).
   - 인터페이스 · 상위 클래스 메서드면 구현 · 오버라이드와 인터페이스 타입으로 부르는 곳까지 찾는다.
   - 같은 이름의 다른 정의를 부르는 호출부를 섞지 않는다. 수신 객체 타입 · include 된 파일로 확인한다.
3. **테이블**: 대상 함수(와 대상이 직접 부르는 DAO · 쿼리)가 읽는 테이블 · 뷰와 쓰는 테이블(INSERT · UPDATE · DELETE · MERGE)을 구분해 적는다.
   - 뷰를 읽으면 뷰 정의(`db/` 아래 스키마 파일 등)를 찾아 원본 테이블까지 적는다. 모듈 밖이라는 이유로 건너뛰지 않는다.
   - 같은 테이블을 읽거나 쓰는 **다른** 함수 · 쿼리를 저장소 전체(`legacy/` 전 모듈, `modern/`, `db/`)에서 찾는다. 같은 DB 를 레거시와 `modern/api` 가 함께 쓴다는 점을 잊지 않는다. 트리거 · 뷰 · 프로시저도 포함한다.
4. **규칙 연결**: `docs/<모듈명>/BUSINESS-RULES.md` 가 있으면 읽고, 근거 `파일:줄번호` 가 대상 함수 · 호출 경로의 줄 범위와 겹치거나 같은 테이블 · 컬럼을 다루는 규칙 ID 를 연결한다. 연결 이유(겹치는 줄 · 컬럼)를 함께 적는다. 파일이 없으면 "BUSINESS-RULES.md 없음"이라고 적는다. 문서의 규칙은 참고일 뿐이며 코드와 다르면 코드를 따르고 차이를 적는다.
5. **테스트 케이스 제안**: 경로 · 테이블 · 규칙마다 수정 전에 현재 동작을 고정할 테스트를 제안한다. 입력 · 기대 결과 · 근거를 적고, 경계값(`<` · `<=` · 빈 값 · 캐스팅)과 오류 경로를 빠뜨리지 않는다. 이미 있는 테스트(`characterization/`, `src/test/`)가 덮는 것은 그 파일 경로를 적고 "기존"으로 표시한다.

## 출력 형식
```markdown
## 영향도 분석: <대상 이름> (`파일:줄번호`)

### 1. 영향받는 화면
| 화면 · URL | 진입 파일 · 메서드 | 근거 |
|---|---|---|

### 2. 호출 경로 (진입점 → … → 대상)
- P1: `GET /search.php` → `buildSearchQuery` (`search.php:722`) → **대상** (`search.php:42`)
  ```php
  <호출 줄 인용>
  ```

### 3. 영향받는 테이블
| 테이블 · 뷰 | 대상의 접근 (R/W) | 근거 | 같은 테이블을 쓰는 다른 코드 (R/W, 근거) |
|---|---|---|---|

### 4. 관련 규칙 ID
| 규칙 ID | 연결 이유 | 근거 |
|---|---|---|

### 5. 수정 전에 확보할 테스트 케이스
| # | 대상 경로 · 규칙 | 입력 | 기대 결과(현재 동작) | 근거 | 기존/신규 |
|---|---|---|---|---|---|

### 6. 추적 한계
- <검색으로 확정하지 못한 경로, 의심 이유, 확인한 검색 패턴, 사람이 확인할 방법>
```

## 추적 한계로 적을 것 (검색으로 못 찾는 경로)
- PHP: 변수 함수(`$fn()`), `call_user_func(_array)`, 변수로 조립한 `include` · `require`, 문자열로 만든 URL · `header('Location: ...')`.
- Java · Spring: 리플렉션, AOP · 이벤트 리스너 · `@Scheduled`, 템플릿에서 문자열로 조립한 URL, 설정 파일로 주입되는 빈.
- SQL: 동적 SQL(`EXEC(@sql)`, `sp_executesql`), 트리거, 다른 DB · 배치 · 외부 시스템이 부르는 프로시저.
- JS · TS: 문자열 키로 고른 함수, 동적 `import()`.
- 저장소 밖에서 부르는 경우(운영 스케줄러, 다른 서비스)는 항상 가능성으로 적는다.
