# RCA 리포트 마스킹 규칙

리포트(`docs/rca/<시나리오>.md`)를 저장하기 전에 아래 규칙을 모두 적용한다. 본문 · 표 · 원문 발췌 · 명령 출력 인용 모두에 적용한다.

## 유형별 규칙

| 유형 | 찾을 것 (예) | 바꾸는 값 |
|---|---|---|
| IP — 구분이 필요한 것 | 원인 설명에서 서로 다른 역할로 나오는 서버 · 단말 IP | 역할 별칭: `API-1`, `API-2`, `교사단말A` ~ `교사단말D` 등 |
| IP — 구분이 필요 없는 것 | 그 밖의 IP | 앞 두 옥텟만 남기고 `10.20.x.x` 처럼 적는다 |
| 이메일 | `name@domain` | `[EMAIL]` |
| 학생 식별자 | `STU-<숫자>` (쿼리 문자열 · 앱 로그 메시지) | `***` |
| 토큰 · 세션 ID | `Authorization: Bearer …`, 세션 · 스레드 ID 처럼 토큰 형태인 값 | `[TOKEN]` |
| 비밀번호 · 접속 문자열 | `password=…`, `jdbc:…://user:pass@…` | `[SECRET]` |

## 역할 별칭

- 별칭은 역할을 드러내게 짓는다(응답한 API 서버 = `API-1`, 연결을 거부한 예비 서버 = `API-2`, 리포트를 요청한 교사 단말 = `교사단말A` …).
- 같은 IP 는 리포트 전체에서 같은 별칭을 쓴다.
- 별칭의 뜻은 리포트 첫머리에 한 줄로 적는다. 예: `> 마스킹 별칭: API-1 = 응답한 API 서버, API-2 = 연결을 거부한 예비 API 서버, 교사단말A ~ 교사단말D = 리포트 요청을 보낸 교사 단말 4대. 그 밖의 IP 는 10.20.x.x 로 적었다.`
- 별칭이 어떤 실제 IP 인지는 리포트에도, 다른 파일에도 적지 않는다.

## 적용 방법

- 원본 값은 처음부터 리포트에 옮기지 않는다. 명령 출력을 인용할 때 그 자리에서 바꿔 쓴다.
- 마스킹 전 원본을 임시 폴더 · 스크래치 파일에 복사하지 않는다. 대응표(별칭 ↔ 실제 값)를 파일로 남기지 않는다.
- 저장 직전에 리포트를 `grep -nE` 로 다시 검사한다: IPv4 패턴, `@[A-Za-z0-9.-]+\.[a-z]+`, `STU-[0-9]`, `Bearer `, `password`, `jdbc:`. 별칭과 `10.20.x.x` 외에 걸리는 값이 없어야 한다.
- 문서 끝에 유형별 적용 건수를 한 줄로 적는다. 0건인 유형도 적는다.
  예: `마스킹 적용: IP 52건(역할 별칭 49 · 10.20.x.x 3) · 이메일 0건 · 학생 식별자 0건 · 토큰 · 세션 ID 1건 · 비밀번호 · 접속 문자열 0건`
