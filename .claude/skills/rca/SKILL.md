# RCA 리포트 작성

- 대상 로그: `incident-logs/$ARGUMENTS/`
- 결과 리포트: `docs/rca/$ARGUMENTS.md`
- 인자가 비었거나 폴더가 없으면 시작하지 않고 `incident-logs/` 아래 폴더 목록을 보여 준 뒤 묻는다.
- 명령의 로그 경로는 `L/` 로 줄여 쓸 수 있다(리포트에 그 뜻을 적는다).

## 절차

1. **수집 범위** — 원인 추정은 하지 않는다.
   - 파일을 통째로 읽지 않는다. `wc -l` · `head` · `tail` · `grep -c` · `grep -n` · `awk`/`cut` 집계로만 본다.
   - 파일마다 줄 수, 기록 기간, 시각 형식, 타임존을 표로 적는다. 타임존 표기가 없으면 다른 파일의 같은 사건으로 맞춰 확인한다. UTC · epoch 는 KST 변환 규칙과 검증 예를 적는다.
   - "이상" 줄(레벨 · 상태 코드)과 제외한 줄을 정의하고, 분 단위 이상 건수로 평소 수준과 이상 구간(전조 · 영향)을 나눈다.
   - 앞뒤 여유를 근거와 함께 정해 최종 수집 범위를 확정한다. 개인정보 · 비밀값이 든 파일을 표시한다.
2. **타임라인** — 수집 범위 안의 사건을 KST 한 시간축으로 합친다.
   - 모든 줄에 출처 `파일:줄번호` 와 80자 이내 원문 발췌를 붙인다. 집계 줄은 사용한 명령을 적는다.
   - 파일 간 몇 초 안의 사건은 **(선후 불확실)** 로 표시한다. 반복 메시지는 "첫 발생, 이후 N건/분"으로 묶는다.
   - 해석은 쓰지 않는다.
3. **가설** — 2개 이상, 계층(코드 · DB · 트래픽 · 인프라 · 배포/설정)을 나눠 세운다.
   - 먼저 가장 많이 나온 메시지를 "증상"으로 분리하고, 모든 가설이 설명해야 할 관측(O1, O2 …)을 적는다.
   - 가설마다 지지 근거(`파일:줄번호`), **반증 조건**(이것이 확인되면 틀림), 확인 방법(실행할 명령 · 볼 코드 위치)을 쓴다.
4. **반증 시도와 판정**
   - 먼저 로그로 반증 조건을 확인한다. 명령과 결과를 R 번호로 기록하고 가설마다 유지 · 기각 · 판단 불가를 매긴다. "유지"는 확정이 아니다.
   - 유지된 가설은 로그에 찍힌 클래스 · 설정 이름을 코드 · 설정 파일 `파일:줄번호` 와 대조한다. 값은 파일에서 읽은 것만 쓴다.
   - 최종 **채택 · 기각**을 적고, 채택 가설로도 설명되지 않는 부분을 숨기지 않는다. 운영 DB 에는 접속하지 않는다.
5. **리포트 작성** — `docs/rca/$ARGUMENTS.md` 에 아래 순서로 쓴다.
   - 요약(무엇이 · 언제, 직접 원인, 확대 요인, 확신 수준) → 1 수집 범위 → 2 타임라인 → 3 가설과 검증
   - 4 원인(직접 원인 사슬 · 배경 원인) → 5 근거 로그 줄(원인 문장마다 `파일:줄번호` · 발췌)
   - 6 수정안(파일 · 무엇을 어떻게, 코드는 고치지 않음) → 7 재발 방지(장치 · 막는 것)
   - 8 모니터링 항목(지표 · 임계값 · 평소 · 이번에 울렸을 시각 · 근거)
   - 9 확인하지 못한 것(판단 못 한 부분 · 없었던 자료 · 다음을 위해 남길 것)
6. **마스킹** — 리포트를 저장하기 전에 `.claude/skills/rca/masking-rules.md` 의 규칙을 적용한다.
   - 저장 전에 리포트 전체를 다시 검사해 남은 원문 값이 없는지 확인하고, 문서 끝에 유형별 마스킹 건수를 적는다.

## 하지 말 것

- 로그에 없는 줄을 인용하지 않는다. 줄 번호와 발췌는 인용 전에 `sed -n '<N>p'` 로 확인한다.
- 가장 많이 나온 오류를 곧바로 원인이라고 부르지 않는다. 그것이 나올 상태가 된 이유를 가설로 설명한다.
- 원본 로그와 소스 코드를 수정하지 않는다. 산출물은 `docs/rca/$ARGUMENTS.md` 하나다.
- 마스킹 대응표(별칭 ↔ 원래 값)를 파일로 남기지 않는다.
- 마스킹 전 원본을 임시 폴더에 복사해 두지 않는다. 원본 값은 저장할 문서에 처음부터 옮기지 않는다.
